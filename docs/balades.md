# Balades

Open it through **Tous mes outils → Balades**. It is a separate space from the daily workspace: it holds walk tracks and the spots ("repères") along them. Planning only gains one action per saved walk, described below. Phase 1 is private to the business: in account mode the owner and trusted carers can record, import, edit, delete and export; clients and professionals have no access (the API answers 403). Static mode has no roles, so anyone using that browser can use it. There is no entry on the public site.

Controls and messages support French, English (**All my tools → Walk tracks**), Italian, German and Spanish. Track names, notes and dog names stay as entered. Use HTTPS or localhost for GPS, Screen Wake Lock and secure browser APIs such as recording IDs. Allow location access when starting a recording; if denied, enable it for this site in the browser settings. Importing and managing saved tracks do not require location permission.

## Recording a walk

**Enregistrer une balade** starts `navigator.geolocation.watchPosition` with high accuracy. A fix is kept only when its reported accuracy is 35 m or better and it is at least 4 m from the last kept point. The screen shows distance, elapsed time, kept points and the last accuracy. **Terminer la balade** opens the save form (name, date, dogs picked from the registered dogs); **Abandonner** asks for confirmation and erases the recording.

At least two kept points are needed to save. If there are fewer, the recording remains available to resume or discard. At the 20,000-point limit, the next eligible fix stops recording and opens the save form. Finishing stops GPS and releases the wake lock; saving the named track is a separate action.

The page asks for a Screen Wake Lock while recording and says whether it got one. **A web page cannot record with the screen off.** iOS Safari and Chrome pause geolocation when the phone locks or the page goes to the background, so the screen must stay on for the whole walk. For long walks, record with a phone GPS app and import its GPX file. Recording through a locked screen needs a native app.

The in-progress recording is written to this browser at start, every 10 seconds and when finishing (IndexedDB `dogcare-balades-v1`, store `drafts`, key `account:<business_id>` or `static`). Staff using the same business in the same browser share that recovery slot; it is not per user. After a reload or crash, the list offers **Reprendre l’enregistrement**, **Terminer maintenant** or **Abandonner**, with the same deletion confirmation as during recording. These actions appear only after recovery loading finishes. Elapsed time is wall-clock time since the start, so a resumed recording counts the gap. The recording ID also becomes the saved track's ID, so saving a recovered recording again after a save whose response was lost updates that track instead of adding a duplicate. The draft never leaves the browser; it is deleted when its geometry is saved or the recording is explicitly abandoned. Importing another track preserves it. If local persistence fails, a warning stays visible through recording, finishing and cancelling the save form; the recording remains in memory and can be resumed while the page stays open. Leaving the Balades page does not stop a recording. Each draft carries a recording ID and a write token. Replacing or deleting it compares the expected ID and token in one IndexedDB transaction, so another tab cannot overwrite or delete a newer recovery copy. Older drafts without these fields remain recoverable and gain them on their next write. Writes within one recording are ordered; discard waits for pending writes before deleting. A conflicting tab keeps its recording in memory with the same recovery warning. After a confirmed discard or a successful save that applies recording geometry, cleanup reconciles the recovery card with the current stored draft without deleting a newer copy.

When a recovered recording already has a saved track, the save form starts with its saved name, date and dogs. Saving replaces the points and duration only if the recording has more points and starts with every saved coordinate in the same order. This check runs again against the latest snapshot on conflict retry. Otherwise only the name, date and dogs edits are applied: the saved geometry and duration stay intact, and the recovery copy remains available, including when both point lists are identical.

Only recording points and recovery metadata persist in this draft. Unsaved names, dates, dog selections, imported tracks and spot/editor values remain in memory across internal navigation and language changes; save them before reloading or closing. Cancelling a recorded-track save keeps its recoverable recording; cancelling an import discards that pending import.

## Import and export

**Importer un GPX** reads the file in the browser and opens a form to review before saving. Track points (`trk/trkseg/trkpt`) are used; a file without them falls back to route points (`rte/rtept`). All tracks/segments become one line, so a gap between segments is drawn and measured as a straight line. Each `wpt` becomes a spot of type **Pause** with its name (or description when unnamed) as the note, unless its `<type>` is one of the Balades types (files exported here). A recognized type uses `<desc>` as the note (empty when absent, since `<name>` is only the exported type label) and preserves `<cmt>` as the official rule for **Toléré**. The date noted comes from the waypoint's valid `<time>` in UTC, else today. The track name comes from `metadata/name`, then `trk/name`, then `rte/name`, then the file name; the date from the first timed point in the device's local time, else today. Duration uses the first and last timed points, capped to 0–604,800 seconds, or stays unknown with fewer than two timestamps. Invalid or out-of-range point times become `null`; coordinates are rounded to six decimal places.

Files are refused with a localized message (French by default) when they are larger than 8 MiB, cannot be parsed as XML, declare a DOCTYPE, are not GPX, have a point without valid coordinates, have fewer than two points, more than 20,000 points or more than 200 waypoints. Imported names are cut to 120 code points and notes/rules to 500; unsupported control characters are removed. The 8 MiB file cap accommodates exported tracks at the point and spot limits, including Unicode and XML-escaped notes; the 600,000-point business limit and 32 MiB API request cap are unchanged.

**Exporter le GPX** downloads GPX 1.1 with the track (`trkpt` with `time` when known) and every spot as a `wpt` carrying `<time>` (the date noted), `<name>` (type label), `<desc>` (note), `<cmt>` (official rule, Toléré only) and `<type>` (`pause`, `danger`, `interdit`, `laisse` or `tolere`).

GPX is a track exchange, not a full Balades backup: it omits internal IDs, selected dogs, Planning links, `source`, and separately saved track date/duration. Reimport creates a new track and derives its date/duration from point times. An empty spot note stays empty on reimport. Elevation, GPX extensions and the original imported file are not retained.

## Manage saved tracks

**Vos tracés** lists newest dates first, then names, with distance, duration, dogs and spot count. Choose **Ouvrir**, then **Modifier** to change the name, date or selected dogs; track geometry is not edited. Track and spot forms accept today or an earlier date. Removing a selected dog also removes that dog's Planning links from the track. **Supprimer** asks for confirmation before removing a track, its spots and its links; it leaves Planning attendance and tariffs unchanged. Export first if you want to keep a GPX copy. Spots can be edited or deleted individually; spot deletion and **Retirer** on a Planning link save immediately without a confirmation dialog.

## Spots

Open a track, choose **Ajouter un repère**, then tap the map (or **Placer au centre de la carte**). Types: **Pause** (water, lake, shade, bench…), **Danger**, **Chiens interdits**, **Laisse obligatoire** and **Toléré**. Each has a note of up to 500 characters and the date it was noted. A **Toléré** spot also has a **Règle officielle**; the two are shown side by side with "Une pratique constatée sur place, pas une autorisation." Markers use a distinct colour and icon per type, a legend sits under the map, and each marker is a button whose accessible name is the type and note. The list of spots under the map is the keyboard-accessible version. Latitude and longitude can be corrected in the form, which is also how a spot is placed when the map cannot be shown; both are required, and a blank field is refused with a message instead of placing the spot at 0, 0.

## Link to a walk in Planning

Under the walk checklist in **Planning**, each walk saved for the selected day shows **Ajouter le tracé**. It opens Balades for that dog and date: pick an existing track (**Relier à cette balade**), or record or import one; the new track is linked when saved. Afterwards the walk shows **Voir le tracé**. The link is stored on the track as `walkRefs: [{date, dogId}]` and the dog is added to the track's dogs. One track can serve several dogs on the same walk, and a dog's walk on a given day links to one track at most (relinking moves it). The daily snapshot is unchanged; unticking a walk in Planning leaves the link on the track, visible under **Balades du Planning** with **Retirer**.

## Map and privacy

The map uses MapLibre GL JS 6.13.0, bundled under `assets/vendor/balades/` (see its README and checksums) and loaded only when the Balades page needs a map. The basemap is OpenFreeMap's `liberty` style (`https://tiles.openfreemap.org/styles/liberty`, no key). The browser fetches the style, fonts and tiles for the area being viewed from OpenFreeMap, which therefore learns the approximate area shown and the viewer's IP address. Tracks, spots, notes and dog names are never sent there. If WebGL is missing, the page says the map cannot be shown; tracks and spots still work. The deployment's `Permissions-Policy` must allow `geolocation=(self)` (see `deploy/dogcare.caddy`).

## Storage and API contract

`balades-model.js` and `api/balades.py` validate the same snapshot:

```json
{ "version": 1, "tracks": [ {
  "id": "track-1", "name": "Parc de Saint-Cloud", "date": "2026-10-21", "dogs": ["billie"],
  "points": [[48.8402, 2.219, 1792900000], [48.8411, 2.2205, 1792900060]], "durationSec": 60, "source": "record",
  "walkRefs": [{ "date": "2026-10-21", "dogId": "billie" }],
  "spots": [{ "id": "spot-1", "type": "tolere", "lat": 48.84, "lon": 2.22, "note": "…", "rule": "…", "noted": "2026-10-20" }]
} ] }
```

All fields are required and extra fields are rejected. IDs follow the accounting identifier format (1–81 ASCII letters, digits, `_` or `-`, starting with a letter or digit); track IDs are unique in the snapshot and spot IDs within their track. `name` is nonblank, at most 120 code points; text follows the accounting control-character rules. `points` are `[latitude, longitude, unix seconds or null]`, 2 to 20,000 per track. Coordinates are finite numbers in −90–90 latitude and −180–180 longitude; timestamps are integers from 0 to 4,102,444,800 or `null`. `durationSec` is `null` or an integer from 0 to 604,800. Dates are valid `YYYY-MM-DD` values in years 0001–9999; only the UI restricts them to today or earlier. `source` is `record` or `import`. Up to 50 unique dog IDs and 50 walk links per track; each link's dog must be among the track's dogs, and a date/dog pair appears once in the whole snapshot. These references are not validated against the daily registry or attendance. Up to 200 spots per track; `note` and `rule` are at most 500 code points each, and `rule` must be empty unless the type is `tolere`. Limits per business: 500 tracks, 600,000 points and 30 MiB of compact UTF-8 JSON in total, including all spot notes and rules. Both validators enforce the aggregate size; the browser reports the capacity error before sending. This leaves room for the request envelope under the API's 32 MiB body cap.

Static mode stores the snapshot in IndexedDB `dogcare-balades-v1` (store `state`, key `current`). A save compares the stored text with the version this tab loaded inside one readwrite transaction, so a stale tab cannot overwrite another tab's work. Static tracks and recording drafts are not automatically imported into account mode, and account saves do not update the static snapshot. Switching back to static mode restores that browser's separate records. Demo reset preserves both tracks and drafts. Invalid or unreadable snapshots block Balades saves and hide Planning track links until loading succeeds; other daily workflows remain available.

Account mode uses the additive table `business_balades (business_id, snapshot, revision)`. Existing businesses start with `{ "version": 1, "tracks": [] }` and revision `0`; existing tables, records and sessions are unchanged. Balades have their own revision so recording a walk never conflicts with Planning or care edits, and the shared care revision and legacy import eligibility are untouched. Whole-database [backups](private-beta-release.md#backup-and-recovery) include saved tracks, spots and links; browser-only recording drafts and static records are outside that backup.

- `GET /api/balades` (session cookie) → `{ "ok": true, "business_id", "revision", "balades" }` for owner and trusted carer; 403 for client and professional; 401 when signed out. Balades are not part of `/api/state`.
- `PUT /api/balades` with `{ "balades": <full snapshot> }`, `X-DogCare-Business: <business_id>` and `If-Match: "<balades revision>"`. Success returns the same shape with the next revision. A stale revision returns 409 (428 without `If-Match`) with `"conflict": true`; invalid snapshots return 400; nothing is written in either case. On a revision conflict, the UI offers **Recharger et réessayer**, which reloads and reapplies the pending change to its original target. Reload and replay share one busy state; navigating away cancels an unsubmitted retry. New tracks and spots keep their creation IDs across resubmissions, so retrying a committed save whose response was lost does not append a duplicate. Editing after a conflict removes the abandoned retry message and button; the form can be submitted again with the new values. Failed saves retain form values, and a target deleted elsewhere produces an explicit message without discarding unsaved input.

PUT is a full replacement: preserve all tracks to retain, or send `{ "balades": { "version": 1, "tracks": [] } }` to remove them all. Use `Content-Type: application/json` and the session cookie; the [common origin/body rules](../README.md#slice-1-api) apply. A missing business header returns 428 and a mismatched one 409, both with `reload_required: true`; a database write failure returns 500. Failed writes leave the snapshot and revision unchanged. A business-switch conflict requires reloading the account, not replaying its draft into another business.

After `DogCareAPI.ready` succeeds, `DogCareAPI.balades()` fetches the snapshot; `balades(snapshot, revision)` replaces it. Success resolves to `{ok: true, revision, balades, businessId}`; failure resolves to `{ok: false}`, optionally with `status` and `conflict`. Calls have the adapter's 15-second deadline and do not join the care-write queue or update its cache/revision; `whenSaved()` does not wait for them. `BaladesStore` owns the loaded snapshot/revision and save conflicts. Staff boot loads it for Planning links; only map rendering loads MapLibre. Tabs/devices do not refresh each other's snapshots automatically.

## Checks

```sh
node --test tests/test_balades_model.js
python3 -m unittest tests.test_balades_api -v
uv run --python 3.12 --with playwright==1.61.0 python -m unittest tests.test_balades_browser -v
```

The browser tests run both modes at 390 × 844 with mocked geolocation and a stubbed map style (no network): they record a walk, place a **Toléré** spot by tapping the map, reload, export and import GPX, link a Planning walk, and check overflow and the console. Regressions cover abandoned conflict retries, deleted targets, failed-save input, draft ownership across tabs, delayed recovery loading, confirmed draft deletion, failed draft persistence, lost-response retries, late Wake Lock requests, delayed map loading and snapshot reuse in Planning. Node and Python checks include aggregate UTF-8 capacity below the individual count limits; Node also round-trips a maximum-size exported GPX with Unicode and XML escapes. Headless Chromium needs `--use-angle=swiftshader --enable-unsafe-swiftshader` for WebGL. A real phone, a real GPS fix, native wake-lock behaviour and live OpenFreeMap tiles are not exercised.
